# Always-on Claude

**내 Mac에서, 내 Claude로. 언제 어디서든 폰에서 말하면 Mac 앱이 움직이고, 상시 비서가 먼저 알려주며 중요한 건 확인합니다. 그렇게 운영하며 얻은, 어떤 AI 에이전트에도 통하는 "실전 운영 노하우"를 시행착오 사례로 공개합니다.** · [English](README.en.md)

이 저장소는 두 가지를 담았습니다. ① **AI 에이전트를 무인으로 안정적으로 운영할 때 겪는 문제와 해법(범용 교훈)**, ② 그것을 항상 켜 둔 Mac에서 Claude로 구현한 **사례**입니다. 사례는 휴대폰 메신저(텔레그램)로 요청하면 일정·미리 알림·메일·메시지·날씨를 챙기고 결과를 돌려주는 개인용 AI 비서이며, 이를 **따라 만들 수 있는 일반화한 예제·템플릿**도 함께 담았습니다. 운영 원본(개인 설정·기억·정책 원문)은 담지 않았습니다. 비슷한 것을 만들려는 분이 같은 함정을 피하고 최소 구성부터 세우도록 돕는 것이 목적입니다.

> ⚠️ **면책**: 개인 사용 기록이며 보증하지 않습니다. 메신저·메일 자동화는 서비스 약관 위반이나 계정 제재의 가능성이 있고(특히 비공식 방식), 타인의 대화를 다루는 일이라 법적·윤리적 책임은 각자에게 있습니다. 여기에 실제 개인정보·설정·키는 포함돼 있지 않습니다(자세한 내용은 [보안·개인정보](docs/security-and-privacy.md)).

## 한눈에 보기
| 질문 | 답 |
|---|---|
| 핵심 | ① 내 기기에서 로컬 앱 자동화 ② 내 Claude로 구동 ③ **메신저(텔레그램 등)로 상시 원격 제어** — 폰에서 말하면 집의 Mac이 실행하고 결과를 돌려줌 |
| 무엇인가 | 메신저로 요청 → 맥에서 실행 → 결과를 메신저로 회신하는 상시 비서 |
| 바탕 | Claude Code(CLI). 사용 한도가 있어 설계에 반영해야 함(L-104). 요금·한도 정책은 바뀔 수 있으니 최신 약관 확인 |
| 항상 켜 두는 법 | tmux 세션 + 감독 스크립트 + 매일 정해진 시각 재시작 |
| 정기 업무 | LaunchAgent가 하루 2번 보고(아침·저녁, 일정·마감·메일·날씨)와 백그라운드 감시를 실행 |
| 안전 원칙 | 되돌리기 쉬운 일은 먼저 하고 나중에 보고, 되돌리기 어려운 일(발송·삭제·금전·권한)만 승인 |
| 공개 범위 | 구조 설명 + 일반화한 교훈 + **일반화한 예제 코드·템플릿**. 정책 원문·권한 설정 원본·기억 파일은 제외 |
| 범용 vs 환경 특화 | **범용** 교훈은 모델·OS와 무관하게 통합니다. **환경** 표시는 해당 환경에서만 직접 적용되고 원리만 참고하세요. 다른 환경에서 따라 해 본 검증은 [미확인] |
| 공유용 소개 | https://always-on-claude.vercel.app (카톡·메신저 공유용 한 페이지, 썸네일 포함) |
| 처음 시작 | [따라 만들기](docs/build-your-own.md) → [예제](examples/) · [템플릿](templates/) |
| 망가졌을 때 | [복구 가이드](docs/recovery.md) |

## 왜 이 프로젝트인가 (원격 접속·화면 조작 기능이 이미 있어도)
| 관점 | 설명 |
|---|---|
| 부품이 아니라 시스템 | 원격 접속은 "멀리서 세션에 들어가는 통로", 화면 조작은 "손"입니다. 둘 다 사람이 시킬 때 움직입니다. 이 프로젝트는 시키지 않아도 정해진 시각에 보고하고, 놓친 일을 먼저 찾고, 실패하면 재시도하고, 고장 나면 스스로 알립니다. **상시성과 자율성**은 부품만으로 생기지 않습니다. |
| 화면 없는 경로 우선 | 화면 조작은 느리고 사용자가 기기를 쓰는 동안 방해가 됩니다. DB 읽기, 스크립트, 커넥터로 처리하고 화면은 마지막 수단으로 둡니다. 매일 무인으로 돌리려면 이쪽이 안정적입니다. |
| 안전과 신뢰의 설계 | 무엇을 먼저 하고 무엇을 승인받는지, 무인 실행에서 무엇을 막는지, 중복과 거짓 완료를 어떻게 막는지는 도구가 대신 정해 주지 않습니다. 이 저장소의 교훈이 그 실체입니다. |
| 나에게 맞춘 판단 기준 | 내 업무 일정, 기억, 선호에 맞춘 규칙은 범용 기능이 가져갈 수 없고, 시간이 지날수록 가치가 커집니다. |
| 따라 하는 사람의 지도 | 도구가 쉬워질수록 직접 만드는 사람이 늘고, 그 사람들이 부딪힐 문제는 여기 기록된 문제와 같습니다. |

> 공식 기능이 좋아지면 직접 만든 실행 부분(감독, 정기 실행, 원격 접속)은 공식 기능으로 갈아 끼우는 것이 맞습니다. 그래도 남는 것은 **무엇을 맡기고, 언제 묻고, 어떻게 믿을 수 있게 운영하는가**에 대한 규칙과 경험이며, 이것이 이 프로젝트의 본질적인 가치입니다.
