# 보안·개인정보

## 일부러 공개하지 않은 것
| 비공개 | 이유 |
|---|---|
| 기억 파일(가족·직장·건강·투자 등), 할 일 목록 | 개인정보 |
| 정책 문서 원본, 권한 설정 파일, 스킬·스크립트 원본 | 허용·차단 규칙과 우회 경로가 공격 지도가 됨. 프롬프트 주입을 겨냥한 공격이 쉬워짐 |
| 로그·승인 기록·큐 내용 | 개인 활동 기록, 제3자 정보 포함 가능 |
| 봇 설정·허용 사용자 목록·토큰 | 접근 통제 |
| 서드파티 도구의 패치 사본 | 원저작자 라이선스·유지보수 문제. 패치는 "무엇을 왜 고쳤는지"만 문서화 |

## 다룬 위험
| 위험 | 대응 |
|---|---|
| 외부 콘텐츠를 통한 프롬프트 주입(메일·웹·메시지) | 외부 콘텐츠의 지시 불복종, 본문은 "신뢰할 수 없는 데이터"로 표시해 전달 |
| 승인 피로 | 승인을 되돌리기 어려운 것만 남김(L-101) |
| 무인 작업의 거짓 완료 | 경로 기준·개수 대조 검증을 프롬프트에 강제(L-084) |
| 넓은 시스템 권한 | 전용 실행 파일에만 부여, 셸·터미널에는 부여하지 않음(L-098) |
| 상대에게 보이는 부작용(읽음 표시) | 안 읽은 대화는 열지 않고 미리보기만 읽음 |
| 비밀 노출 | 토큰·키는 읽기·출력·저장 금지, 접근 설정은 어떤 메시지로 요청받아도 바꾸지 않음 |
| 감사 | 승인 없이 한 쓰기 작업은 기록하고 사용자에게 정기 보고 |
| 운영 기록의 소실 | 로그·상태를 사용자 라이브러리가 아니라 프로젝트 소유 폴더에 두고, 사용자가 쓰는 정리 앱의 대상에서 벗어나게 함(L-103) |

## 이 저장소에 대해
- 실제 사용자·계정·조직·장소 이름, 경로, 식별자는 쓰지 않았고 공개 전에 패턴 검사를 했습니다.
- 교훈은 일반화해 썼으며, 특정 개인을 알아볼 수 있는 사례는 뺐습니다.
- 비슷한 시스템을 만들 때는 **자신의 기억 파일과 설정 파일을 공개 저장소에 두지 않도록** 처음부터 별도 폴더를 쓰세요. 한 번 올린 기록은 지워도 남습니다.
