# 한계와 미확인

솔직하게, 아직 검증하지 못했거나 불완전한 부분입니다.

| 항목 | 상태 |
|---|---|
| 새 정기 일정(아침·저녁)의 장기 안정성 | 통합한 직후라 관찰 중 |
| 승인 요청 빈도 분석 | 승인 기록이 남지 않아 명령 기록을 규칙에 대어 본 추정치. 실제와 다를 수 있음 |
| 메신저 승인 버튼의 폰 실제 터치 | 입력 방식으로만 시험, 실기기 확인 미완 |
| 사전 훅이 커넥터 호출을 실제로 막는지 | 입력 시험만 했고 실제 차단 순간은 미확인 |
| 한도 도달 후 대기·재시도 동작 | 단위 시험만 했고 실제 한도 상황은 미확인 |
| 로그를 지운 주체 | 정리 앱의 실행 시각과 일치하는 정황만 있고 삭제 목록 기록은 없음(L-103) |
| 점검 알림이 "기록 삭제"와 "실행 안 됨"을 구분하는지 | 구분하지 못함(과제) |
| 메시지·메일 검토의 기억 품질 | 시작 단계, 오탐·중복 사례를 계속 수집 중 |
| 격리 브라우저의 리다이렉트 방어 | 처음 주소만 검사 |
| 메신저 자동화의 약관 위험 | 접근성 방식도 제재 가능성이 0은 아님 |
| 모델이 시간이 지나면서 같은 지시를 다르게 해석할 가능성 | 정기 점검으로 완화할 뿐 보장하지 않음 |

이 문서의 숫자·시각은 한 사람의 환경에서 나온 값이며 다른 환경에서는 달라질 수 있습니다.

## 예제·가이드 자체의 한계
| 항목 | 상태 |
|---|---|
| 예제 코드 | 시험한 범위는 [예제 목록](../examples/README.md)의 "시험" 열대로만. 세션 시작 명령(`supervisor.sh`의 `AI_CMD`)은 버전마다 달라 **미확인** |
| 따라 만들기 문서 | 저자 환경(macOS, 텔레그램)에서 만든 흐름을 일반화한 것. 다른 OS·메신저는 검증하지 않음 |
| 복구 가이드 | 복구 시간은 추정치. 실제 복구 훈련은 하지 않음 |
