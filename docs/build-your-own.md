# 따라 만들기 (최소 구성에서 시작)

목표: 휴대폰 메신저로 요청하면 맥에서 실행하고 결과를 메신저로 돌려주는 상시 비서. 아래 순서대로 **한 단계씩 확인하고 넘어가세요.** 한꺼번에 만들면 어디서 깨졌는지 찾기 어렵습니다.

## 준비물
| 항목 | 설명 |
|---|---|
| 항상 켜 둘 PC | 맥(잠자기 방지 설정 필요). 이 문서의 예제는 macOS 기준 |
| Claude Code + 구독 | API 키가 아니라 기존 구독 범위로 쓰는 구성. **사용 한도(5시간 등)가 있어서 설계에 반영해야 함(L-104)** |
| 메신저 봇 | 이 프로젝트는 텔레그램. 봇을 만들고 **내 계정만 허용**하도록 설정 |
| tmux | 세션을 터미널 없이 항상 켜 두기 위해 |

## 단계 (각 단계 끝의 "확인"을 통과해야 다음으로)
| 단계 | 할 일 | 확인 | 관련 |
|---|---|---|---|
| 1. 작업 폴더 | `~/assistant` 만들고 `CLAUDE.md`([템플릿](../templates/CLAUDE.template.md))와 `memory/`, `state/logs/` 생성 | 폴더에서 Claude Code가 규칙을 읽고 답한다 | 설계 원칙 |
| 2. 메신저 연결 | 봇 토큰을 **권한 600 파일**에 저장(코드에 넣지 않음), 허용 사용자 지정. [`tg-lib.sh`](../examples/tg-lib.sh)로 전송 시험 | 내 메신저로 시험 메시지가 도착한다 | 보안·개인정보 |
| 3. 상시 세션 | [`supervisor.sh`](../examples/supervisor.sh)를 launchd KeepAlive로 실행, 매일 새벽 재시작 | 세션을 죽였을 때 5초 안에 되살아난다 | 구조 |
| 4. 요청→실행→회신 | 메신저로 요청하면 **회신 도구**로 답하게 한다(터미널 출력은 사용자에게 안 보임) | 폰에서 질문 → 폰으로 답 | |
| 5. 쓰기 안전장치 | 일정·알림을 만드는 스크립트는 [`write-guard.sh`](../examples/write-guard.sh)처럼 중복 검사를 **쓰기 경로**에 넣는다 | 같은 항목을 두 번 시켜도 한 번만 만들어진다 | L-100 |
| 6. 정기 보고 | [`run-daily.sh`](../examples/run-daily.sh) + [launchd 템플릿](../examples/launchd)으로 아침·저녁 2번만 | 지정 시각에 보고가 온다. 한도 걸린 날도 재시도로 도착한다 | L-102, L-104 |
| 7. 자기 점검 | [`health-check.sh`](../examples/health-check.sh)를 **다른 스케줄러**로 30분마다. 완료 기록으로 판단 | 작업을 일부러 막으면 알림이 오고 복구되면 "복구됨"이 온다 | L-104 |
| 8. 로그·백업 | 로그는 프로젝트 폴더(`state/logs`)에, [`rotate-logs.sh`](../examples/rotate-logs.sh)와 [`backup.sh`](../examples/backup.sh)를 스케줄 | 로그가 정리 앱·시스템 정리에 안 지워진다. 백업 폴더에 날짜별 사본이 생긴다 | L-103 |
| 9. 권한은 마지막에 | 앱 제어·메시지 읽기 같은 넓은 권한은 필요할 때 **전용 실행 파일에만**(셸·터미널 X) | 해당 기능만 동작하고 다른 곳은 막혀 있다 | L-098 |

## 자주 막히는 곳
| 증상 | 원인 | 해결 |
|---|---|---|
| 스케줄러로 돌린 스크립트만 파일·앱 접근 거부 | 권한은 터미널/tmux에 있고 스케줄러 자식 프로세스에는 없음 | 권한 있는 tmux 서버 안에서 같은 스크립트를 다시 실행 (L-083) |
| 승인 버튼이 안 눌림 | 봇 폴링을 다른 프로세스가 점유 | 답장 키보드 방식 (L-085) |
| 승인 요청이 너무 잦음 | 허용 목록 문제가 아니라 역할·정책이 섞임 | 승인을 되돌리기 어려운 것만으로 (L-101) |
| "완료"라는데 실제로는 안 됨 | 무인 작업자가 엉뚱한 경로를 집음 | 경로 기준·개수 대조를 프롬프트에 강제 (L-084) |
| 정기 작업이 어제 실패했는데 계속 알림 | 종료 코드가 다음 성공까지 남음 | 완료 기록으로 판단 (L-104) |
| 어느 날 로그가 통째로 사라짐 | 정리 앱이 사용자 라이브러리 로그를 지움 | 로그를 프로젝트 폴더로 (L-103) |

## macOS·Claude 외 환경에서 따라 할 때
원리는 같고 도구만 바꿉니다. **다른 환경에서 직접 검증하지는 않았습니다** [미확인].

| 이 문서의 구성 | 다른 환경에서 대체 |
|---|---|
| launchd(LaunchAgent) | Linux: systemd timer 또는 cron / Windows: 작업 스케줄러 |
| tmux 상시 세션 | 공통(Linux·macOS). Windows는 WSL 또는 서비스 관리자 |
| 텔레그램 봇 | 다른 메신저의 봇 API(Slack, Discord 등) — 전송 함수 하나만 바꾸면 됨 |
| 애플 앱(캘린더·알림·메시지) | 해당 OS의 일정·알림 API 또는 CalDAV 등 |
| macOS 권한(L-083, L-098) | 해당 없음 또는 OS별 권한 모델로 대응(서비스 계정 권한 등) |
| Claude Code `-p` 실행 | 다른 모델·에이전트의 비대화형 실행 명령. 한도 처리(L-104)와 도구 제한(L-105)은 그대로 적용 |
| zsh·BSD `date` | bash 또는 GNU `date -d`로 교체(예제의 시각 파싱 부분) |

## 이 문서가 다루지 않는 것
- Claude Code의 메신저 채널 연결 옵션과 권한 모드는 버전마다 바뀌므로 **각자 사용 중인 버전의 공식 문서를 따르세요** [미확인].
- 허용·차단 규칙의 실제 목록과 정책 원문은 일부러 공개하지 않습니다(프롬프트 주입 공격의 지도가 되기 때문). 원칙과 템플릿만 제공합니다.
