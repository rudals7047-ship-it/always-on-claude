# 구조

```
휴대폰(텔레그램)  ⇄  봇  ⇄  [상시 세션: tmux 안의 Claude Code]  ──▶  맥 앱·파일·웹
                                      ▲
 정기 작업(launchd) ─ claude -p ──────┘   결과는 텔레그램 Bot API로 직접 전송
```

## 구성요소
| 구성요소 | 역할 | 메모 |
|---|---|---|
| 상시 세션 | 메신저 요청을 받아 처리하고 회신 | tmux 안에서 항상 실행, 감독 스크립트가 죽으면 다시 띄움, 매일 새벽 정해진 시각에 재시작(맥락 초기화) |
| 정기 보고 | 하루 2번(아침·저녁) | launchd가 한 실행기를 호출하고, 실행기는 단계(브리핑·주간·점검·검토)를 독립적으로 돌려 하나가 실패해도 다음이 돈다 |
| 백그라운드 감시 | 변화 감지, 작업 큐, 자기 점검 | 보고가 아니라 "이상할 때만" 알린다. 자기 점검은 감시 대상과 분리 |
| 작업 큐 | 며칠 걸리는 일·자는 동안의 일 | 15분마다 한 덩어리씩 진행, 사용 한도에 걸리면 풀릴 때까지 쉬고 이어감, 완료·막힘·승인 필요를 메신저로 알림 |
| 기억 | 파일(`memory/`)과 스킬 | 대화는 매일 초기화되므로 중요한 것은 파일로. 개인정보 보호를 위해 이 저장소에는 포함하지 않음 |
| 원격 제어 | 메신저 | 폰의 메신저가 명령과 회신 채널. 내 계정만 허용하고 계정 보안(2단계 인증)이 곧 이 시스템의 보안 |
| 승인 | 메신저 버튼 | 세션 자체의 도구 승인은 플러그인 내장 중계, 스크립트가 만든 승인은 답장 키보드(L-085) |
| 도구 제한 | 무인 실행 경로 | 사람이 없는 정기 실행에는 발송·삭제·(필요 없으면) 웹 도구를 막고, 사람이 있는 세션은 발송을 승인으로 둔다(L-105) |
| 로그·백업 | 운영 기록 보존 | 로그는 프로젝트 폴더에 두고 분기마다 압축·용량 보고(L-103), 작업 폴더는 클라우드 폴더에 매일 날짜별 백업 |
| 격리 브라우저 | 웹 조사 | 실행마다 새 임시 프로필, 창 없음, 내부망·로컬 주소 차단, 결과는 "신뢰할 수 없는 콘텐츠"로 표시 |

## 읽기·쓰기 원칙
- **읽기는 래퍼 스크립트로**: 캘린더·미리 알림·메일·메시지를 읽는 스크립트를 따로 만들고 `읽기 전용`으로 둔다(DB는 읽기 모드로만 연다). 느린 앱 제어 방식은 최후의 대체 경로.
- **쓰기는 래퍼 하나로**: 항목을 만들기 전에 중복을 검사하고, 만든 항목에는 "비서가 만들었다"는 표시를 붙여 사용자가 구분·되돌리기 쉽게 한다(L-100).
- **권한은 최소 단위로**: 접근성 같은 넓은 권한은 셸이 아니라 기능을 줄인 전용 실행 파일에 준다(L-098).

## 정기 업무의 모양
| 시각 | 하는 일 |
|---|---|
| 아침 | 오늘 일정·마감·메일·뉴스 요약. 요일별로 주간 리뷰·일정 점검을 덧붙임 |
| 저녁 | 내일 마감·날씨, 그리고 하루 메시지·메일을 검토해 일정은 등록하고 기억할 맥락은 파일에 요약 기록 |
| 상시(분 단위) | 변화 감시, 작업 큐, 자기 점검 |
| 분기 | 로그 압축(90일 지난 줄 보관 압축) 후 총용량 보고 |

시각은 사용자의 하루 리듬에 맞춘 예시일 뿐이며, 보고를 쪼개기보다 두 번으로 모으는 편이 읽기 편했습니다(L-102).
