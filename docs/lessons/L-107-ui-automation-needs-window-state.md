# L-107 접근성 기반 읽기: 창이 닫히면 실패한다

**상황/증상:** 정기 메시지 검토에서 메신저 앱 한 곳만 "창이 유일하지 않음"이라는 오류로 실패했다. 다른 경로(DB 직접 읽기, 메일, 커넥터)는 정상이라 전체 판단에는 지장이 없었다.

**원인:** 앱은 실행 중이었지만 열린 창이 0개였다. 읽기 도구는 메인 창이 정확히 1개일 때만 동작하는데, 오류 이름이 "유일하지 않음"이라 0개일 때도 같은 오류가 나서 원인이 가려졌다. 사용자가 창을 열자 바로 정상 동작했다.

**해결/방법:**
- 오류 코드는 두고, 호출하는 스크립트에서 "메인 창이 닫혀 있거나 여러 개임, 창을 열어 두면 해결"로 번역한다. 사용자 알림에도 그 문장을 그대로 넣는다.
- 권한이 묶인 바이너리는 다시 빌드하지 않는다(손쉬운 사용 권한이 풀릴 수 있음).
- 창이 필요 없는 경로가 있으면 우선한다: DB 직접 읽기, AppleScript, 커넥터(API), 시스템 서비스.

**일반화:** 화면(접근성) 기반 자동화는 앱의 창·화면 상태가 사전 조건이다. ① 모호한 오류 이름은 호출 쪽에서 원인 문장으로 번역하고, ② 사용자가 할 행동을 알림에 넣고, ③ 가능하면 API·DB·커넥터 경로를 우선한다. 화면 조작은 마지막 수단이다.

**근거:** 창 개수 0 확인 → 창을 연 뒤 목록 정상 출력, 검토 스크립트 시험 통과. 창이 최소화된 상태에서 읽히는지는 [미확인].
