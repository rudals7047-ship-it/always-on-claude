# L-106 링크 미리보기 제목 잘림과 캐시

**상황/증상:** 공유용 한 페이지를 만들어 카카오톡으로 보냈더니 썸네일 이미지는 정상인데 제목이 "Always-on Claude: 내 기기에서, 내 Claude로, …"처럼 두 줄에서 잘려 보였다. 제목(`og:title`)에 소개 문구까지 길게 넣은 것이 원인이었다.

**해결/방법:**
- 제목(`og:title`)은 서비스 이름만 짧게(한 줄), 소개 문구는 설명(`og:description`)으로 옮긴다.
- 고쳐서 배포한 뒤에도 메신저 쪽 캐시 때문에 예전 모양이 남는다. 서버가 새 태그를 내보내는지는 크롤러 사용자 에이전트로 직접 요청해 먼저 확인한다(서버 문제와 캐시 문제를 가른다).
- 캐시는 주소 문자열 단위로 저장된다. 공식 디버거에서 초기화해도 넣은 주소가 보낸 주소와 한 글자라도 다르면(끝의 `/` 등) 적용되지 않는다. 가장 확실한 방법은 같은 페이지를 가리키는 새 주소(`?v=2` 같은 쿼리)로 다시 보내는 것이다.
- 초기화가 안 먹는 경우가 있다. 가장 의심되는 원인은 **초기화한 주소와 대화방에 붙인 주소의 문자열이 달랐던 것**이다(`https://…` / `https://…/` / 프로토콜 없음 / `www`는 각각 다른 키로 저장된다는 개발자 포럼 보고가 있으나 공식 확인은 없음 [추정]). 대화방에 붙이는 형태를 하나씩 디버거에 넣어 초기화하고, 안 되면 `?v=` 새 주소로 보낸다(이것은 직접 확인함).
- 이미지를 바꾼 경우에는 이미지 주소의 `?v=`가 같이 바뀌어 초기화만으로 갱신된 적이 있고, 문구만 바꾼 이번에는 그렇지 않았다. 이 차이가 영향을 줬는지는 [추정]이다. 이미지는 주소(파일명이나 `?v=`)를 바꾸는 것이 가장 확실하다는 안내가 있다.
- 이미 보낸 말풍선은 나중에 바뀌지 않는다. 새로 보내야 한다.

**일반화:** 링크 미리보기는 "내 서버가 내보내는 태그"와 "메신저가 저장한 사본"이 따로다. 고친 뒤 안 바뀌면 서버 응답을 먼저 확인하고, 서버가 맞으면 캐시 키(주소)를 바꿔서 해결한다. 제목은 짧게, 부가 설명은 설명 칸에 둔다.

**근거:** 수정 배포 후 서버 응답 확인, 새 주소로 보냈을 때 정상 표시됨(사용자 확인).
