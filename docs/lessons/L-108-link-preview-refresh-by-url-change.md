# L-108 이미지 주소를 바꾸면 캐시 초기화 없이 갱신된 사례

**상황/증상:** 공유 페이지의 썸네일을 새로 만들어 배포했다. 메신저의 캐시 초기화 도구를 쓰지 않았는데도 사용자 쪽 미리보기가 새 썸네일로 바뀌어 보였다(사용자 관찰).

**이번에 바뀐 것(확인):** 이미지 주소가 호스트·경로·`?v=` 해시 모두 바뀌었고 이미지 내용도 바뀌었다. 페이지 설명 문구도 함께 갱신했다.

**왜 알아서 갱신됐나(추정):** 미리보기 캐시가 이미지 주소 단위라면 새 주소는 캐시에 없어 새로 읽혔을 수 있다. 서비스가 주기적으로 다시 읽었을 가능성도 있어 어느 쪽인지는 [미확인]이다. 이미 보낸 말풍선이 바뀐 건지 새로 보낸 것만 바뀐 건지도 확인하지 않았다.

**해결/방법:** 이미지 주소의 `?v=`를 이미지 내용 해시로 빌드 때 자동 갱신하고, 가능하면 호스트나 경로도 바꾼다. 그래도 옛 모습이면 서비스의 초기화 도구나 새 주소로 다시 보낸다.

**일반화:** 미리보기 갱신은 "캐시를 지운다"보다 "캐시에 없는 주소를 내보낸다"가 더 확실한 편이다. 이미지는 내용 해시를 주소에 넣어 자동으로 바뀌게 설계하고, 갱신 여부는 사용자 화면에서 최종 확인한다.

**근거:** 배포 후 라이브 페이지의 이미지 주소 변경과 새 이미지 응답을 확인했고 갱신은 사용자가 확인했다. 원인은 추정.
