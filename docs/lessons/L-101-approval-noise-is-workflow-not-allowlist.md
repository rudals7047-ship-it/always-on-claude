# L-101 승인 잡음의 원인은 허용 목록이 아니었다

**상황/증상:** 텔레그램으로 요청하면 Bash 승인 요청이 계속 오고, 사용자는 개발 세션·상시 세션·텔레그램을 구분하고 싶지 않다고 했다.

**분석(상시 세션 기록 6개, Bash 154건):**
- [추정] 현재 허용 규칙으로 약 111건(72%)이 승인 대상. 대부분 인라인 `python3 -`, 설정 파일 복사, git, clone 같은 **개발 작업**이고 읽기용 스크립트 호출은 대체로 통과했다.
- [확인] 허용 목록을 손질한 정리안(읽기성 명령 추가 등)을 같은 기록에 모의 적용하니 111 → 108건으로 거의 줄지 않았다.
- [확인] 정책 문서는 "삭제·외부 통신은 승인"이라는데 설정은 `rm`·`mv`·`curl`·`launchctl`을 허용으로 두는 **불일치**가 있었다(중요한 것은 통과, 사소한 것은 막힘).
- 허용 규칙은 명령 **앞부분 글자**로 일치해서 `cd … &&`, `bash`, 파이프, 변수 설정이 앞에 붙으면 같은 스크립트도 승인을 묻는다.

**해결/방법:**
1. 정책을 "되돌리기 어려운 것만 승인"으로 다시 정의하고, 설정을 그에 맞춘다(삭제를 허용에서 승인으로 이동, 쓰기·이동·정리는 선조치 후보고).
2. 승인이 필요한 일상 작업은 인라인 코드 대신 `scripts/` 래퍼로 만들어 규칙에 맞춘다.
3. 모드 자체(명령마다 묻는 기본 모드)를 자동 모드로 바꾸는 권한 완화는 사용자가 직접 실행하도록 안내한다(에이전트가 자기 권한을 풀지 않는다).

**일반화:** 승인이 잦아지면 사람이 습관적으로 누르게 되어 정말 위험한 승인도 무력해진다. 승인 목록은 "위험도"에 맞추고, 소음의 원인(명령 모양, 역할 혼재)은 구조로 푼다.

**근거:** 2026-11-24 transcript 분석과 모의 적용. 실제 승인 요청 기록은 남아 있지 않아 규칙 해석에 의존한 값이다 [추정].
