# L-103 운영 로그는 사용자 라이브러리가 아니라 프로젝트 소유 폴더에

**상황/증상:** 자기 점검이 "오늘 정기 작업 완료 기록이 없다"고 연달아 알렸다. 확인해 보니 정기 실행 기록과 감시 기준선 등 사용자 로그 폴더(`~/Library/Logs/...`) 안 파일이 일주일치 통째로 사라져 있었다(파일 생성 시각이 모두 같은 시각 이후).

**원인(정황):** PC 정리 앱이 그 시각에 정리를 실행한 기록(앱 자체 기록의 마지막 정리 시각)과 일치했고, 같은 시각 AI 세션의 도구 호출은 전 세션에서 0건이었다. 앱에 삭제 목록 기록이 없어 확정은 못 했다. 사용자 로그 폴더는 정리 앱의 일반적인 정리 대상이다.

**실수에서 배운 것:** 처음에 "주변 폴더도 같은 시각에 새로 생겼다"를 근거로 들었지만, 수정 시각을 생성 시각으로 잘못 읽은 것이었다. `ls -l`의 시각은 수정 시각이고, 생성 시각은 `stat`의 별도 옵션이다. 사용자가 "너 말고는 지울 주체가 없지 않냐"고 되물은 덕에 세션 기록과 앱 기록을 시각으로 대조하게 됐다.

**해결/방법:**
- 로그·감시 기준선·점검 상태를 프로젝트 소유 폴더(작업 폴더 아래 `state/logs`)로 이전. 스크립트·스케줄러 설정의 경로를 일괄 치환하고, 설치본은 백업, 기존 파일은 복사로 이전, 옛 폴더는 승인 없이 지우지 않음.
- 실행 중인 상시 세션은 재시작 때 새 경로를 읽도록 두고 스케줄러 쪽만 재등록. 재등록 후 점검 시험 실행과 새 폴더 기록을 확인.
- 점검 알림이 "기록 없음"이라고 말할 때 "기록이 지워졌다"와 "실행이 안 됐다"를 구분하는 것은 남은 과제.

**일반화:** 무인 자동화의 실행 기록은 "사용자가 정리해도 되는 곳"에 두지 않는다. 원인 추적은 "누가 했나" 추정 전에 의심 도구의 자체 기록(마지막 실행 시각)과 세션 기록을 시각으로 대조하고, 근거로 쓰는 값이 생성 시각인지 수정 시각인지 먼저 확인한다.

**근거:** 이전 후 점검 시험 실행 문제 0건, 새 폴더에 감사·점검·감시 기록 확인. 정리 앱이 실제로 로그를 지웠는지는 [미확인].
