# L-104 한도 실패 재시도 · 종료 코드 알림 오탐 · 센티널 출력 판정

**상황/증상:** 저녁 정기 실행 두 건이 "5시간 사용 한도 도달"로 실패했다(세션 기록으로 확인). 그 뒤 ① 스케줄러의 마지막 종료 코드가 다음 성공 때까지 남아 자기 점검이 같은 실패를 반복 알림, ② 알림 문장이 줄바꿈 대신 `\n` 글자로 표시, ③ 선제 알림 감시가 "판단 결과 NO_REPORT"처럼 꾸며 쓴 출력을 `정확히 NO_REPORT`가 아니라는 이유로 사용자에게 그대로 보냈다.

**해결/방법:**
- 한도 도달은 별도 종료 코드(75)로 구분하고, 실행기가 해제 시각까지(최대 6시간) 기다려 **그 단계를 1회만** 재시도한다. 한도 실패는 즉시 알림 대신 재시도한다.
- 자기 점검은 "오늘 완료 기록이 있는가"로 정기 작업의 성공을 판단하고, 스케줄러 종료 코드는 완료 기록이 없는 작업에만 쓴다(오래 남는 종료 코드는 오탐 원인).
- 센티널(NO_REPORT) 판정은 정확 일치 대신 "문구가 있고 출력이 짧음"으로 완화한다. 알림 문장을 만들 때는 줄바꿈을 실제 줄바꿈 값으로 넣는다.
- 수정 전 스크립트는 백업하고, 문법 검사와 단위 시험(판정·시각 파싱)으로 확인한다.

**일반화:** 무인 LLM 실행은 ① 외부 한도·장애를 "실패"가 아니라 "대기 후 재시도" 상태로 설계하고, ② 감시자는 오래 남는 신호(종료 코드)보다 행위 기록(완료 로그)을 보며, ③ 모델이 약속한 출력 형식을 어길 수 있다고 가정해 판정을 느슨하게 한다.

**근거:** 수정 후 문법 검사·점검 시험 실행 문제 0건·단위 시험 통과. 한도 대기 후 재시도가 실제로 동작하는지는 [미확인](실제 한도가 걸려야 확인 가능).
