# L-100 중복 등록은 "쓰기 경로"에서 막는다

**상황/증상:** 매일 메시지를 검토해 일정을 자동 등록하게 했더니, 첫 실행에서 공유 캘린더에 이미 있던 병원 일정을 미리 알림으로 다시 만들었다. 스킬에 "등록 전 확인"을 적었지만 모델이 빠뜨릴 수 있다.

**원인:** [확인] 등록 대상(캘린더, 미리 알림)이 여러 저장소로 나뉘어 있고, 한쪽만 조회하면 다른 쪽 항목이 안 보인다. 지시문은 권고일 뿐 강제가 아니다.

**해결/방법:**
1. 같은 날의 **모든 캘린더(공유 포함)와 미완료 미리 알림**을 함께 조회해 제목 핵심어(괄호·시각·"예약" 같은 흔한 말 제거)가 겹치면 중복으로 보는 검사 스크립트를 만든다. 시각만 같은 별개 일정은 통과시킨다(처음엔 시각 일치도 막았다가 오탐을 확인하고 고침).
2. 검사를 **쓰기 래퍼 안에 내장**한다(중복이면 만들지 않고 전용 종료 코드).
3. 커넥터로 직접 등록하는 경로는 **PreToolUse 훅**이 같은 검사를 하고 중복이면 호출을 막는다. 사용자가 중복을 원할 때만 설명란의 표시어로 우회한다.
4. 막히면 새로 만들지 않고 "이미 등록돼 있음"으로 보고하게 한다.

**일반화:** 되돌리기 어려운 반복 실수는 프롬프트 규칙이 아니라 경로의 검사로 막는다. 조회 실패 시에는 막지 않고 경고만 하여 정상 등록을 가로막지 않는다.

**근거:** 2026-11-24 중복 사례 재현 후 래퍼 시험(생성 0건 확인)과 훅 입력 4종 시험. 실제 커넥터 호출이 훅에 막히는 순간은 [미확인].
